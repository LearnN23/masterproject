LESSON 2: Identifying and Clarifying Technical Problems

A. LESSON OVERVIEW

Lesson Number & Title: Lesson 2: Identifying and Clarifying Technical Problems

Allocated Learning Duration: 150 Minutes (2.5 Hours)

Occupational Relevance: In Malaysian technical helpdesks and BPO centers (e.g., Concentrix JA003, Inphosoft JA009, Micro Technology Solution JA016, Evoxt JA014), frontline agents must isolate technical faults quickly and accurately. Customers often describe problems using vague language ("My app isn't working", "The internet is down"). Support agents need structured diagnostic questioning skills to identify whether an issue is caused by account credentials, software glitches, network connectivity, or hardware errors before attempting troubleshooting.

Measurable Learning Objectives:By the end of this 150-minute lesson, Thai IT undergraduate learners will be able to:

Differentiate between open-ended diagnostic questions (for broad problem gathering) and closed confirmation questions (for pinpointing specific error details).

Construct indirect diagnostic questions ("Could you tell me what error message appears?") to isolate technical faults politely without making the user feel interrogated.

Paraphrase and confirm vague customer statements using reflective check structures ("So if I understand correctly, you can log in, but the dashboard fails to load?").

Perform a 45-second diagnostic clarification spoken response in a simulated support interaction to isolate a user authentication or network connectivity issue, achieving a minimum score of "3" across all rubric criteria.

B. ATTENTION-GRABBING OPENING HOOK

Workplace Context: Level-1 IT Helpdesk at a Shared Service Center in Cyberjaya, Malaysia.

The Problem / Communication Mistake: An IT support agent named Ken receives a call from an employee reporting: "My portal is broken!" Without asking any clarifying questions, Ken immediately guides the user through a 15-minute complete browser re-installation. At the end of the process, the user reveals: "Oh, I forgot to mention—my home Wi-Fi was turned off." Ken wasted 15 minutes of Average Handling Time (AHT) because he failed to ask basic diagnostic questions to isolate the issue first.

Reflective Question for Students:

What diagnostic questions should Ken have asked in the first 30 seconds?

How can you transform a vague customer complaint into specific technical facts using polite English?

Occupational Importance: In Malaysian contact centers, Average Handling Time (AHT) and First Contact Resolution (FCR) are key performance indicators (KPIs). Jumping straight to solutions without clarifying the problem increases handling time, leads to incorrect troubleshooting, and frustrates customers.

D. EXPLICIT TEACHING OF SENTENCE STRUCTURES AND LANGUAGE USE

1. Language Pattern 1: Indirect Questions for Fault Isolation

========================================================================================

LANGUAGE PATTERN 1: INDIRECT QUESTIONS FOR FAULT ISOLATION

========================================================================================

Form / Syntax Pattern:

  [Polite Lead-in] + [Question Word: what/where/when] + [Subject] + [Verb in Statement Order]?

  Lead-ins: "Could you tell me...", "Would you mind specifying...", "May I ask..."



Communicative Function:

  Eliciting specific technical error details (error messages, timing, device parameters) without sounding demanding or interrogative.



Explanation in Thai (คำอธิบายภาษาไทย):

  เมื่อต้องการถามข้อมูลเทคนิคเชิงลึก การใช้คำถามตรงขึ้นต้นด้วย "What is...", "Why did..." อาจฟังดูเหมือนการซักจำลองหรือตำหนิตัวผู้ใช้ ภาษาอังกฤษในสายงาน Tech Support จึงนิยมแปลงเป็น "Indirect Questions" โดยใช้คำขึ้นต้นสุภาพ เช่น "Could you tell me..." หรือ "Would you mind specifying..." แล้วเรียงลำดับประโยคตามหลังแบบประโยคบอกเล่า (Subject + Verb) ห้ามสลับ กริยา-ประธาน



Contextualized Workplace Examples:

  Example 1: "Could you tell me what error message appears on your screen?"

  Example 2: "Would you mind specifying when this issue first started occurring?"

  Example 3: "May I ask whether you are connecting via mobile app or web browser?"



Common Learner Errors & Corrections:

  x Incorrect: "Could you tell me what is the error code?" (Word order error: 'is the error code')

    ✓ Correct: "Could you tell me what the error code is?"

  x Incorrect: "What error message you see?" (Missing auxiliary in direct question)

    ✓ Correct: "Could you please describe the error message you see?"

  x Incorrect: "Why your system crashed?" (Abrupt direct question)

    ✓ Correct: "Would you mind telling me what happened right before the system crashed?"

2. Language Pattern 2: Reflective Paraphrasing & Confirmation Checking

========================================================================================

LANGUAGE PATTERN 2: REFLECTIVE PARAPHRASING & CONFIRMATION CHECKING

========================================================================================

Form / Syntax Pattern:

  [Reflective Starter] + [Summarized Customer Problem Clause] + [Confirmation Tag]?

  Starters: "So if I understand correctly...", "Just to confirm...", "To make sure I have this right..."



Communicative Function:

  Restating vague or complex customer descriptions in clear technical terms to verify accurate problem comprehension before initiating troubleshooting.



Explanation in Thai (คำอธิบายภาษาไทย):

  การทวนความ (Paraphrasing) เป็นทักษะสำคัญในการสื่อสารบริการ เพื่อให้แน่ใจว่าเจ้าหน้าที่เข้าใจปัญหาตรงกับลูกค้าล้านเปอร์เซ็นต์ โดยใช้ประโยคเกริ่นนำ เช่น "So if I understand correctly..." ตามด้วยสรุปอาการปัญหาแบบกระชับ แล้วปิดท้ายด้วยคำถามยืนยัน เช่น "...is that correct?" หรือ "...am I right?"



Contextualized Workplace Examples:

  Example 1: "So if I understand correctly, your password works on mobile, but you are locked out on desktop; is that correct?"

  Example 2: "Just to confirm, the payment was deducted from your bank, but no order confirmation email arrived, am I right?"

  Example 3: "To make sure I have this right, the connection drops every time you turn on the VPN software?"



Common Learner Errors & Corrections:

  x Incorrect: "You say app broken, yes?" (Overly casual, lacks professional structure)

    ✓ Correct: "So if I understand correctly, the application freezes upon launch, is that right?"

  x Incorrect: "I know your problem already." (Dismissive of customer context)

    ✓ Correct: "Just to confirm, you are experiencing a gateway timeout error during checkout?"

E. GUIDED EXAMPLES AND MODEL DIALOGUES

Model Dialogue 2.1: Technical Support Fault Isolation (Mobile App Authentication)

Workplace Context: Technical Service Desk at Concentrix Malaysia (JA003).

Interaction Type: Inbound Call — Mobile Banking App Authentication Error.

========================================================================================

MODEL DIALOGUE 2.1: DIAGNOSTIC FAULT ISOLATION

========================================================================================

Agent (Maya):    "Thank you for calling Concentrix Technical Support. My name is Maya. How may I assist you today?"

                  [Communication Purpose: Lesson 1 Opening & Offer of Assistance]



Caller (Mr. Roy): "Hi! Your mobile banking app is completely useless! I tried logging in to transfer money, but it won't let me in!"



Agent (Maya):    "I am sorry to hear that you are having trouble logging in, Mr. Roy. I can certainly help you troubleshoot this issue right now. Could you tell me what happens when you tap the login button?"

                  [Communication Purpose: Empathy & Stage 2 Indirect Diagnostic Question]



Caller (Mr. Roy): "Well, I type my password, the screen spins for a few seconds, and then a message pops up saying 'Authentication Timeout Code 504'."



Agent (Maya):    "Thank you for specifying that error code, Mr. Roy. Would you mind telling me if you are connected via Wi-Fi or cellular mobile data?"

                  [Communication Purpose: Narrow Probing Question for Network Fault Isolation]



Caller (Mr. Roy): "I'm currently connected to my home Wi-Fi network."



Agent (Maya):    "Understood. So if I understand correctly, your app displays an 'Authentication Timeout 504' error while connected to Wi-Fi; is that right?"

                  [Communication Purpose: Stage 3 Reflective Paraphrasing & Confirmation]



Caller (Mr. Roy): "Yes, exactly! That's what happens."



========================================================================================

ANALYSIS & FORMALITY OPTIONS:

Why This Dialogue is Effective:

  1. Agent Maya remains calm and empathetic despite the customer's initial frustration ("useless!").

  2. Maya uses indirect questions ("Could you tell me what happens...", "Would you mind telling me...") to elicit the specific error code (504) and network type (Wi-Fi).

  3. Maya concludes Stage 3 with a precise paraphrasing check ("So if I understand correctly...") to confirm the exact diagnosis before moving to solutions.



Alternative Phrasing for Clarification:

  - Higher Formality: "Would you kindly specify the exact wording of the error message displayed?"

  - Direct Probe (Standard): "Does this error occur on Wi-Fi, mobile data, or both?"

Activity 2.1: Diagnostic Question Classification & MCQ (15 Minutes)

An agent wants to know if a customer's router lights are on. Which indirect question is most grammatically and pragmatically correct?

A) "Could you tell me if the router lights are illuminated?"

B) "Could you tell me are the router lights illuminated?"

C) "Tell me what lights are on router right now."

D) "Why you don't check router lights?"

Answer: A

Explanation: Option A maintains statement word order ("if the router lights are illuminated") following the indirect polite lead-in.

Read the customer statement: "I clicked 'Submit Order', but the page went blank and no invoice came." Select the best reflective paraphrasing response.

A) "Your computer has a virus."

B) "So if I understand correctly, the transaction processed, but the page became unresponsive before displaying an invoice; is that right?"

C) "Give me your invoice number now."

D) "Why did you click submit twice?"

Answer: B

Explanation: Option B restates the vague symptom accurately in professional technical terms and includes a confirmation tag.

Complete the sentence: "Would you mind specifying _____ this error occurs on all web browsers or just Chrome?"

A) weather

B) whether

C) what

D) why

Answer: B

Explanation: "Whether" is used in indirect questions when offering a choice between two alternatives (Wi-Fi vs Mobile Data, All Browsers vs Chrome).

SIMULATED SPEAKING TASK 2.1: GUIDED DIAGNOSTIC CLARIFICATION (PARTIALLY GUIDED)

Workplace Situation:

  You are an L1 Tech Support Executive at Evoxt Sdn Bhd (`JA014`).

  A client rings reporting that their cloud control panel is inaccessible.



Customer Prerecorded Audio Line:

  [Audio Prompt]: "Hi, helpdesk! I'm trying to access my cloud panel, but my browser just says 'Page Cannot Be Displayed'. This is blocking my work!"



Student's Specific Speaking Task:

  Formulate a 30–45 second diagnostic response. Acknowledge the issue calmly, ask an indirect question about whether they are connected via office VPN, and ask what error code appears when they refresh.



Task Parameters:

  - Preparation Time: 45 Seconds

  - Target Response Duration: 30 - 45 Seconds



Model Spoken Response:

  "I understand how frustrating it is to be blocked from your control panel. I can certainly help you troubleshoot this right now. Could you tell me if you are currently connected through the office VPN network? Also, would you mind specifying if any numeric error code displays when you refresh the page?"



Model Effectiveness Analysis:

  - Demonstrates calm empathy in sentence 1.

  - Uses two indirect questions ("Could you tell me if...", "Would you mind specifying if...") to isolate network and software parameters.



Self-Check Checklist for Students:

  [ ] Did I acknowledge the user's issue with empathy?

  [ ] Did I use "Could you tell me if..." or "Would you mind specifying..."?

  [ ] Did I maintain correct statement word order in my indirect clauses?

SIMULATED SPEAKING TASK 2.2: INDEPENDENT TRANSFER TASK (NETWORK FAULT ISOLATION)

========================================================================================

Workplace Situation:

  You are an IT Support Specialist at Leuze Electronic (`JA023`).

  An employee calls saying their industrial scanner software is failing to upload data.



Customer Prerecorded Audio Line:

  [Audio Prompt]: "Hello! My warehouse scanner was working fine this morning, but now it refuses to upload any inventory data to the main server!"



Student's Specific Speaking Task:

  Formulate an independent 45-second diagnostic clarification response. Elicit specific fault parameters (e.g., error lights on the dock, Wi-Fi status, or recent password changes) using indirect diagnostic questions and finish with a paraphrasing check.



Task Parameters:

  - Preparation Time: 45 Seconds

  - Target Response Duration: 35 - 45 Seconds



Model Spoken Response:

  "I can definitely assist you with resolving that scanner upload failure. Could you tell me if the green Wi-Fi indicator light on your scanner dock is currently flashing or solid? Also, would you mind specifying if an error message appears on the scanner screen? So if I understand correctly, the scanner reads the barcode, but fails during the server transfer step, is that right?"



Acceptable Alternative Variations:

  - "I'd be happy to help you look into that upload issue. May I ask whether any warning lights are visible on the scanner unit? Just to confirm, the scanning function works, but data fails to sync with the main inventory database, am I right?"



Common Mistakes to Avoid:

  - Avoid asking direct, blunt questions like "Is Wi-Fi broken?" or "Did you drop the scanner?".

  - Keep statement word order intact after "Could you tell me...".
